# Forge — Data Model → UI Mapping

How every Prisma model in `prisma/schema.prisma` maps to the screens and components in the Forge design system.

## 1. Authentication & Profile

| Model | UI Component | Notes |
|---|---|---|
| `User` | Sign-up / Login, Home header avatar | `email` unique; `passwordHash` nullable so OAuth-only users (Google/Apple) have no password. `currentStreak`, `bestStreak`, `xpPoints`, `tier` (`UserTier`: ROOKIE → LEGEND) power the "Elite Level" badge on the profile card. |
| `Account` | "Continue with Google / Apple" buttons | One row per linked OAuth identity. Unique on `(provider, providerAccountId)` prevents duplicate links; NextAuth-compatible shape. |
| `Session` | Server-side session store | Optional when using JWT strategy; cascade-deleted with user. |
| `UserSettings` | Settings screen | Notification toggles, appearance mode (`LIGHT/DARK/SYSTEM`), accent theme color, language, week-start day. 1:1 with `User` via unique `userId`. |
| `Subscription` | Account / Billing screen | `SubscriptionTier` (FREE/PREMIUM/ULTIMATE) drives paywalls. `status` + `currentPeriodEnd` + `cancelAtPeriodEnd` mirror Stripe lifecycle fields for webhooks. |

## 2. Habits

| Model | UI Component | Notes |
|---|---|---|
| `Habit` | Habit cards ("Hydrate — 2.5 Liters"), Create/Edit habit sheet | `category` enum covers Mindfulness/Focus/Health/Growth/Physical chips. `icon` + `colorTheme` reproduce per-card theming. `targetValue` + `unit` render "10 mins", "20 Pages". `timeWindow` = Morning/Evening selector. |
| `Habit.frequency` | Recurrence picker | `DAILY` (Everyday), `WEEKLY` + `timesPerWeek` ("3x/Week"), `CUSTOM_DAYS` + Postgres enum array `customDays` (Mon/Wed/Fri toggles). |
| `Habit.currentStreak / bestStreak / totalCompletions` | Flame counter on habit card & stats strip | Denormalized counters updated by application logic on check-in; avoids recomputing from logs on every render. |

**Indexes:** `(userId)`, `(category)`, `(userId, isArchived)` for the dashboard list query; `(userId, title)` unique stops duplicate habits.

## 3. Logs & Check-ins

| Model | UI Component | Notes |
|---|---|---|
| `HabitLog` | Check-in button, progress ring ("1.8L of 2.5L"), calendar history view | One row per habit per date — enforced by `@@unique([habitId, date])`. Partial completions: `completed=false` with `valueLogged=1.8`; full completion sets `completed=true` + `completedAt` timestamp. `durationMinutes` supports timed habits. `note` captures quick context. |
| — | Calendar heatmap | Composite index `(userId, date)` makes month-view fetch a single range scan; `userId` is denormalized onto the log for exactly this query. |

## 4. Goals, North Stars & Wall of Victory

| Model | UI Component | Notes |
|---|---|---|
| `Goal` | North Star cards ("52 books", "1,000 Kilometers", "$10,000") | `targetValue`/`unit`/`currentValue` drive the progress bar percentage. `targetDate` shows the countdown; `status` (ACTIVE/COMPLETED/ABANDONED) filters the Active vs. Done tabs. |
| `Milestone` | Milestone checklist ("Book 26: Halfway!") | Ordered sub-goals via `sequenceOrder` (unique per goal). `isCompleted` + `completedAt` render checkmarks and dates. Cascade-deleted with parent goal. |
| `Achievement` | Badge catalog (admin-managed) | Global definitions keyed by stable `code` (e.g. `MEDITATION_MASTER`) so app logic can award badges idempotently. |
| `UserAchievement` | Wall of Victory grid | Join table with earned date; optional `goalId` link (SET NULL if goal deleted — the badge survives). Unique `(userId, achievementId)` = no double awards. |

## 5. Insights, Analytics & Quotes

| Model | UI Component | Notes |
|---|---|---|
| `Quote` | Daily Spark banner | One quote per calendar day via unique `displayedDate`; seeded ~a week ahead so the app always has content. |
| `Insight` | Quick Insights / AI recommendation cards | `type` distinguishes BEST_TIME ("Most consistent at 8:00 AM"), HABIT_CORRELATION, CONSISTENCY_TREND, RECOMMENDATION, STREAK_ALERT. `data` JSON holds computed stats (adherence %, correlation coefficient). `isDismissed` powers swipe-to-dismiss. |
| `AnalyticsSnapshot` | Weekly/Monthly analytics screen | Cached metrics per `(userId, period, periodStart)`: `totalImpactPct`, weekly consistency matrix, best time window, partial-completion count. Regenerated by background job instead of aggregating millions of log rows per request. |

## Integrity & Performance Decisions

- **Cascades:** everything user-owned (`settings`, `subscription`, `habits` → `logs`, `goals` → `milestones`, `insights`, `snapshots`, OAuth accounts/sessions) deletes with the user — GDPR-friendly hard delete.
- **Exception:** `UserAchievement.goalId` uses `SetNull` so deleting a goal never erases an earned badge.
- **Defaults:** all PKs are `cuid()`; timestamps default `now()`; counters default `0`.
- **Money/distance precision:** `Decimal(12,2)` on goals, `Decimal(10,2)` on habits/logs — no float drift on "$10,000" or "2.5L".
- **Date columns** use `@db.Date` (no time component) so timezone-safe day comparisons match UI calendars.
- **Hot paths indexed:** `HabitLog(userId,date)` (calendar), `Habit(userId,isArchived)` (dashboard), `Goal(userId,status)` (active tab), `Insight(userId,generatedAt)` (feed).
- **Password hashing:** seed stores `scrypt$salt$hash` (Node crypto, no native deps). App layer must use the same format or swap in bcrypt/argon2 consistently.
